# Эксплуатация и наблюдаемость

## Назначение

Эксплуатационные инструменты позволяют сопоставлять желаемую топологию,
сгенерированную конфигурацию и наблюдаемое состояние работающей сети.
Они не являются центральным контроллером и не участвуют в выборе
маршрута каждого пакета.

## Основные источники состояния

| Источник | Что сообщает |
|---|---|
| Декларативная модель | Запланированные узлы и связи |
| Сгенерированные файлы | Настройки, подготовленные к развёртыванию |
| Babel и системные маршруты | Реальная достижимость и выбранные пути |
| UCI и статусы служб | Желаемые и применённые локальные политики |
| Логи OpenWrt/systemd | Сбои, перезапуски и диагностические события |
| Измерения iperf3 | Наблюдаемые скорости отдельных направлений |

Визуализация может использовать как плановую топологию из модели,
так и фактические/измеренные параметры. Между этими представлениями
возможны расхождения: появление ребра в модели не доказывает, что линк
сейчас работает, а наличие маршрута не доказывает доступность интернета.

Страница LuCI `Services -> Exit Route` сохраняет режимы и правила устройств
через стандартный UCI `Save / Save & Apply / Reset`. Изменения в `exit_route`
вызывают однократное согласование через procd reload trigger; постоянная
служба продолжает опрашивать Babel по своему интервалу. LuCI читает
фактическое состояние только через `exit-route.sh status`; скрипт не
редактирует пользовательские политики. Ручной `uci commit exit_route`
нужно дополнить `reload_config` или `/etc/init.d/exit-route reload`.
Состояние применения проверяется по `APPLY` и `ERROR` в ответе
`exit-route.sh status`, а также по системным журналам. Если commit или reload
завершился ошибкой, остаётся маркер незавершённого применения; следующая
итерация повторяет commit и reload даже при неизменном UCI. Статус остаётся
`APPLY=ERROR` до успешного reload. Это не заменяет проверку правил ядра.
Строки `HOP` показывают
ближайший gateway и интерфейс маршрута Babel к каждому доступному EXIT,
но не весь многопереходный маршрут. Значение `ACTIVE`
показывает UCI-состояние выбранного маршрута и не заменяет `ip route`
или `nft list ruleset` для диагностики ядра.

## Потоки эксплуатации

**Анализ расхождения:** модель -> сгенерированные конфиги -> состояние
служб и маршрутов -> диагностика конкретной связи или правила.

**Измерение связи:** инвентаризация доступных узлов -> задачи измерения
-> сбор результатов -> визуализация скоростей на схеме топологии.

**Развёртывание:** версия артефактов -> установка/обновление -> проверка
доступности узлов и состояния служб. Отдельно должна оцениваться
возможность потери SSH-доступа при изменении сетевой конфигурации.

## Ограничения

Ни измерение скорости, ни визуализация не являются гарантиями безопасности
маршрутизации. Для проверки `EXIT_FAIL_CLOSED`, правил firewall и реакции
на частичные ошибки нужны испытания на целевой ОС.

Оперативные изменения на работающем роутере не становятся автоматически
частью исходной декларативной модели. При намеренном `sysupgrade -n`
они не обязаны пережить перепрошивку. Это выбранная модель обновлений,
а не автоматически исправляемая потеря состояния.

  `tools/topology_*.py`.

  `deploy_servers.py`.

# Контроль доступа и защита EXIT

## Назначение

Firewall решает, разрешена ли передача пакета между зонами и к локальному
узлу. Маршрутизация выбирает путь; наличие пути само по себе не предоставляет
прав доступа. Для OpenWrt и Linux EXIT применяются разные реализации защиты.

## Защита на роутере

Генератор создаёт зоны только для реально существующих интерфейсов:
`Mesh`, `Exit`, `ExitIPIP`, `TrustedAccess`, `TransitAccess`.
Обычные `lan` и `wan` принадлежат базовой конфигурации OpenWrt.

- `TrustedAccess` разрешает доступ к самому принимающему роутеру.
- `TransitAccess` ограничивает локальный вход и получает DNS-исключение.
- Forwarding между зонами генерируется только для допустимых пар.
- `allow_to_router` и `allow_to_lan` дают точечные разрешения к другим узлам.
- Глобальные правила EXIT создаются генератором; их состояние согласует служба.
- Для устройства отдельные правила могут создаваться и удаляться динамически.

В строгом режиме `EXIT_FAIL_CLOSED` назначения `direct` блокируются на роутере,
а назначения `main` сохраняют более высокий приоритет и обычную маршрутизацию.
Для остальных назначений действует выбранный EXIT. При недоступном
Babel-маршруте служба включает DROP. Если IPIP-маршрут исчез при доступном
Babel marker, сгенерированные `ExitRouteWanGuard*` запрещают выход через
зону WAN. Атомарность применения `network` и `fw4` не гарантируется;
защиту переходных состояний требуется проверять на OpenWrt.
Подробнее: [EXIT](EXIT.md).

## Независимая защита на сервере

EXIT-сервер применяет собственные `iptables`/`ipset` правила и NAT.
Для трафика, приходящего от EXIT-подсетей и направляемого во внешний интерфейс,
сервер запрещает назначения из **обоих** наборов: `main` и `direct`.
Это последняя линия защиты, не зависящая от выбранного режима на роутере.
Отдельно применяется фильтрация BitTorrent с помощью nDPI.

## Владение и ограничения

На OpenWrt `firewall_part` генерируется полностью, а локальная служба EXIT
меняет только управляемые ей правила через UCI. Серверный guard управляется
отдельным скриптом и systemd. Объединять эти механизмы в одну runtime-службу
архитектура не предполагает.

Сервер обновляет оба списка через `ipset swap`, не перестраивая
действующую цепочку `iptables`. Одна защитная цепочка устанавливается
при `network-up` и восстанавливается при отсутствии. Изменение параметров
фильтра применяется повторным `network-up`.

Если выбранный глобальный `EXIT_FAIL_CLOSED` недоступен по Babel, служба включает
`ExitRouteUnavailable*`: `DROP` для глобальной метки `10000` вне `main`.
Индивидуальный EXIT блокируется отдельным правилом по IPv4 клиента.
При выборе `SPLIT_FAIL_CLOSED` сетевой набор `direct` сохраняет обычный WAN;
в `EXIT_FAIL_OPEN` и `EXIT_FAIL_CLOSED` он блокируется даже при отказе EXIT. Для строгих
режимов создаётся `ExitRouteWanGuard*` (а для устройства - `_guard`),
запрещающий WAN fallback при отсутствии IPIP-маршрута. Временные
блокировки при смене режима не создаются.

На OpenWrt порядок применения UCI и реальный порядок правил fw4 нужно
проверять отдельно: исходники описывают намерение, но не доказывают
отсутствие кратковременных утечек при смене режима.

## Инварианты

- Нельзя выпускать `main` или `direct` через внешний интерфейс EXIT-сервера.
- Индивидуальная политика устройства должна быть сильнее глобальной.
- Для `EXIT_FAIL_CLOSED` отсутствие пути не означает разрешение использовать WAN.
- Изменения служебного firewall не должны нарушать работу Babel и overlay.

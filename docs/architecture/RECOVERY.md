# Восстановление после отказов

## Назначение

Система использует несколько независимых механизмов восстановления,
каждый со своей областью ответственности. Не следует смешивать отказ
маршрута, отказ EXIT, потерю DNS upstream и зависание целого роутера.

| Уровень | Кто реагирует | Результат |
|---|---|---|
| Overlay-маршрут | Babel | Выбор другого доступного пути до префикса |
| Интернет-выход | `exit-route` | Пересчёт политики при изменении Babel marker |
| DNS upstream | `dns-failover` | Выбор другого DNS endpoint |
| Длительная потеря связности роутера | `ping-reboot` | Перезагрузка по заданному порогу |
| Службы на сервере | systemd | Управление жизненным циклом компонентов EXIT |

## Границы отказов

Babel определяет достижимость объявляемых префиксов, а не исправность
интернета за EXIT. `exit-route` принимает результат Babel и не вводит
собственный health-check до внешних сайтов или дополнительный hysteresis.

DNS failover проверяет ответы конкретных DNS endpoints; это иной сигнал,
чем маршруты Babel. Отказ DNS не обязан означать отказ EXIT или mesh.

`ping-reboot.sh` проверяет указанные адреса через ICMP. Он сначала требует
серию успешных проверок для взведения; после взведения считает
последовательные неудачи. Отдельный длительный таймер действует,
если служба вообще не смогла взвестись. Это грубое восстановление узла,
а не механизм переключения туннелей.

## Инварианты и компромиссы

- Отказ одного EXIT не должен автоматически менять политики других устройств.
- `EXIT_FAIL_CLOSED` не должен превращаться в WAN из-за недоступности выхода.
- Восстановление DNS не должно требовать перезагрузки роутера.
- Watchdog не должен перезагружать роутер из-за одной случайной потери ping.
- Избыточная логическая топология не защищает от всех общих причин отказа,
  например питания или одного и того же провайдера.

Время реакции определяется периодическими циклами, параметрами служб и
динамикой протоколов. Смена EXIT может нарушить уже установленные сессии.

`exit-route` перезапускается через procd при аварийном завершении.
Одновременные `once` и `run` сериализуются через `flock`, а не через
каталог, который мог бы остаться после `SIGKILL`. Перед UCI commit служба
создаёт в `/tmp` маркер незавершённого reload для `network` или `firewall`.
Если commit или reload завершается ошибкой, маркер остаётся и следующая
итерация повторяет оба действия даже при неизменном UCI. После успешного
reload маркер удаляется; пока он существует, статус сообщает `APPLY=ERROR`.
Маркеры сохраняются при перезапуске процесса, но исчезают при reboot;
после загрузки UCI применяют системные службы OpenWrt.
Дополнительных временных блокировок при смене режима нет.

## Где смотреть исходники

- Управление выходом: `routers/example/files/etc/scripts/exit-route.sh`.
- DNS: `routers/example/files/etc/scripts/dns-failover.sh`.
- Watchdog: `routers/example/files/etc/scripts/ping-reboot.sh`.
- Жизненный цикл на OpenWrt: `routers/example/files/etc/init.d/`.
- Серверные службы: `servers/example/etc/systemd/system/`.

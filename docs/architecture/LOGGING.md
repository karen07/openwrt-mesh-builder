# Диагностика и журналы служб

## Назначение

Скрипты служб записывают важные события и ошибки через стандартный `logger`.
На OpenWrt сообщения попадают в `logread`, на Linux EXIT-серверах - в системный
журнал, доступный через `journalctl`. Для каждого скрипта используется свой тег.

Сообщения имеют стандартные приоритеты syslog: `daemon.notice`,
`daemon.warning`, `daemon.err` и, где необходимо, `daemon.crit`.
Дополнительные сообщения `daemon.debug` доступны при `LOG_DEBUG=1`, если
эта переменная передана процессу, например при ручном запуске скрипта.

Логирование не запускает отдельный мониторинг, не сохраняет историю событий
и не опрашивает сеть повторно ради диагностических сообщений. Ошибки при
повторных попытках могут записываться на каждом цикле.

## OpenWrt

Для просмотра сообщений:

```sh
logread -e exit-route
logread -e dns-failover
logread -e ping-reboot
logread -e update-ipsets
logread -e iperf3-server
```

- **`exit-route`**: запуск и остановка, изменение выбранного маршрута EXIT,
  успешный `network reload` и `firewall reload`, ошибка согласования с указанием
  этапа. При неизменном UCI успешный цикл не создаёт сообщений `notice`.
  Выбор EXIT использует Babel marker route, а не проверку интернета за сервером.
  Сообщение об обновлении сетевого маршрута не подтверждает применение firewall.
- **`dns-failover`**: запуск и остановка, отсутствие DNS endpoints или работающих
  резолверов, переключение upstream, восстановление доменных перенаправлений
  и ошибки применения конфигурации dnsmasq. Успешный перезапуск dnsmasq
  подтверждает завершение команды, но не исправность нового upstream.
- **`ping-reboot`**: запуск и остановка, прерывание начального взведения,
  успешное взведение, потеря и восстановление связи, причины перезагрузки
  и ошибка команды `reboot`. Ход успешного взведения и повторные неудачи
  после взведения доступны в режиме `DEBUG`.
- **`update-ipsets`**: начало обработки, ошибки загрузки и проверки источников,
  количество полученных CIDR, оптимизация, наличие изменений в `direct.txt`
  и результат перезагрузки firewall. Итог обработки списка не гарантирует
  успешного применения firewall. Это отдельный периодический запуск скрипта.
- **`iperf3-server`**: регистрация сервера в procd. Это не подтверждение
  работоспособности процесса. Отдельное логирование подключений не добавлено.

## Linux EXIT-серверы

```sh
journalctl -t awg-server
journalctl -u awg-server-network.service
journalctl -u exit-direct-guard.service
journalctl -t update-ipsets
```

`awg-server.sh` сообщает о запуске и завершении процедуры настройки сети,
вызовах управления AWG и Babel, создании интерфейсов, настройке NAT,
обновлении `ipset`, применении защитных правил и ошибках команд.

Сообщение об успешном вызове `systemctl` подтверждает только результат команды.
Сообщение о завершении `network-down` означает, что выполнена исходная
последовательность очистки; отдельной проверки отсутствия каждого правила
или процесса не производится. Вывод команд остаётся доступен в журнале systemd.

## Ограничения

- Журнал не заменяет проверку маршрутов `ip route` и правил firewall.
- Наличие Babel marker route не подтверждает доступность интернета через EXIT.
- При длительной ошибке некоторые предупреждения могут повторяться с интервалом
  опроса. Специального подавления одинаковых сообщений нет.
- Приоритеты и отображение сообщений зависят от настроек системного журнала.

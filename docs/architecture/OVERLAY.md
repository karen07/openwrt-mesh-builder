# Защищённая межузловая связность

## Назначение

Overlay соединяет узлы в маршрутизируемую L3-сеть поверх чужих IP-сетей,
включая провайдерский NAT. Он предоставляет защищённый транспорт для Babel
и внутренних пакетов, но сам не определяет пользовательскую политику выхода.

## Границы слоёв

| Слой | За что отвечает |
|---|---|
| Underlay | Достижимость внешних IP и UDP endpoints через провайдеров |
| Защищённый overlay | Аутентифицированные AWG/WG-соединения между узлами |
| Маршрутизация | Выбор пути до внутренних префиксов поверх доступных линков |
| EXIT data plane | Дополнительная IPIP-доставка пользовательского IPv4 до EXIT |

Пользовательский пакет, направляемый на EXIT, проходит независимую
инкапсуляцию: внутренний IPv4 внутри IPIP, затем транспорт поверх
защищённого overlay. Путь по mesh может поменяться без смены выбранного EXIT.

## Установка межузловой связности

Настройки обеих сторон строит генератор, используя роли узлов, параметры
линков и управляемые ключи. Leaf за NAT инициирует соединение к публичному
hub; обратные EXIT-соединения используются, когда сервер не предоставляет
входящий публичный endpoint.

Связность зависит от внешнего IP/UDP-транспорта и наличия соответствующих
конфигураций у обоих концов. Overlay предоставляет маршруты и соседства,
но не выдаёт автоматически разрешения на доступ к LAN другого узла.

## Решения и компромиссы

- L3-туннели не превращают распределённую сеть в единый L2 broadcast domain.
- Раздельные overlay и EXIT-передача позволяют выбирать путь и точку выхода
  независимо; за это приходится платить накладными заголовками и MTU.
- Ключи и сетевые идентификаторы создаются/переиспользуются генератором,
  но runtime-обнаружение ключей или автоматическая выдача новых peer не входят
  в задачи Babel.
- Отказ underlay пути может устранить линк; альтернативный маршрут появится
  только если в overlay остались другие живые связи.

# DNS и резервирование резолверов

## Назначение

DNS обслуживает локальное разрешение имён и доступ клиентов к внешним
именам. Он не решает, какой EXIT использовать, и не заменяет маршрутизацию
mesh. Часть DNS-трафика самого роутера имеет отдельную EXIT-политику.

## Состав подсистемы

- `dnsmasq` обслуживает запросы клиентов и локальные записи.
- `https-dns-proxy` предоставляет локальные DoH endpoints.
- `dns-failover.sh` выбирает доступный upstream и обновляет dnsmasq через UCI.
- Генератор создаёт внутренние `router-*.mesh` записи для разрешённых узлов.
- `routers[].dhcp_hosts` в `config.json` описывает локальные
  резервирования IP/MAC и индивидуальные DHCP-опции; нужные теги dnsmasq
  генератор создаёт автоматически. `dhcp_part` полностью генерируется.

DNS failover читает кандидатов из настроенных DoH endpoints и DNS серверов
провайдера. Более приоритетный работающий endpoint выбирается первым;
доступность проверяется DNS-запросом. Служба повторяет проверку периодически,
поэтому после восстановления приоритетного upstream может вернуться к нему.
При отсутствии отвечающих кандидатов используется последний настроенный
endpoint как fallback, а не гарантия успешного разрешения имён.

## Потоки

**Обычный домен:** клиент -> dnsmasq -> выбранный upstream; при DoH
локальный proxy отправляет запрос от имени процесса роутера.

**Разрешённое внутреннее имя:** клиент -> dnsmasq -> сгенерированная
локальная запись для router, без отправки этого имени во внешний DNS.

**Зоны провайдера:** явно заданные доменные зоны направляются на DNS
провайдера, независимо от выбранного основного DoH endpoint.

## Границы и отказоустойчивость

Пакеты самого роутера в основном идут обычным путём, но процесс DoH
использует отдельное правило выбора глобального EXIT. Поэтому режим
`EXIT_FAIL_CLOSED` и состояние exit-маршрута влияют на доступность DoH,
а DNS failover может перейти на провайдерский DNS в рамках своей политики.
Эти две подсистемы не являются единой транзакцией.

Повторные проверки upstream не должны приводить к лишним изменениям UCI,
если эффективное состояние dnsmasq не поменялось.

## Где смотреть исходники

- Служба: `routers/example/files/etc/scripts/dns-failover.sh`,
  `routers/example/files/etc/init.d/dns-failover`.
- Начальные настройки: `routers/example/files/etc/config/https-dns-proxy`.
- Генерация локальных имён: `tools/generate_dhcp.py`.
- Политика DoH и выбор выхода: `tools/generate_exit.py`,
  `routers/example/files/etc/scripts/exit-route.sh`.
